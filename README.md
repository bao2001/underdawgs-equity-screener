# Equity Research Screener — MVP

**MSDSBA Practicum Project**
*A Time-Saving First-Pass Research Tool for Self-Directed Investors*

---

## What it does

Self-directed investors spend 15–45 minutes manually checking each stock before
deciding which companies deserve deeper analysis. This screener automates that
first pass: it aggregates financial metrics, scans 10-K/10-Q filing text for
risk signals, estimates fair value, and returns a ranked research shortlist in
seconds.

**This is a research support tool — not investment advice.**

## Real Financial Statement Dataset

### Where to place the files

The app includes an optional **Model Diagnostics** page that loads a real
XBRL-based financial-statement dataset. Place the three files inside the
`XBRL/` folder next to `app.py`:

```
equity_screener/
├── app.py
├── XBRL/
│   ├── companies.csv
│   ├── indicators_by_company.csv
│   └── companies.json
```

| File | Contents |
|---|---|
| `companies.csv` | `company_id`, `name_latest`, `names_previous` — 12 173 companies |
| `indicators_by_company.csv` | `company_id`, `indicator_id`, yearly values 2010-2016 — ~1.9 M rows, 8 500+ XBRL indicators |
| `companies.json` | Same company lookup in JSON format (used for reference) |

### What the Model Diagnostics page shows

- **Data Coverage** — companies loaded, company-year observations, years covered
- **Indicator Coverage** — which of the 13 target indicators were found vs. absent
- **Target Variable** — clearly labelled as a proxy (see below)
- **Model Validation** — MAE, RMSE, R-squared for Ridge Regression and Random Forest
- **Feature Importances** — top drivers from the Random Forest model
- **Limitations** — explicit list of what the model cannot do

### Proxy model vs. true fair-value model

**No market-cap data is present in this dataset.**
`EntityPublicFloat`, `MarketCapitalization`, and `MarketCap` are absent from all
12 173 companies across all years.

When `market_cap_utils.py` has not been run, the app falls back to a proxy model
using **log(Total Assets)** as its target — a *fundamental size proxy*, not a
market-value estimate. This is clearly labelled in the app.

See the **Market-Cap Model Upgrade** section below for the full pipeline.

### How to run

```bash
cd equity_screener
pip install -r requirements.txt   # includes scikit-learn and yfinance
python3 market_cap_utils.py       # collect market cap data + train model (~2-3 min)
python3 -m streamlit run app.py
```

Navigate to **Model Diagnostics** in the sidebar. If `market_cap_utils.py` has been
run, the true log(market_cap) model is shown; otherwise the proxy model is used.
Streamlit caches the result for the rest of the session.

If the XBRL files are absent, the Model Diagnostics page shows a clear error
message while all other pages continue to work normally using `sample_data.csv`.

## Market-Cap Model Upgrade

The app supports a true market-value model trained on historical market
capitalisation (price × shares outstanding), replacing the balance-sheet proxy.

### How it works

| Step | Script | Output |
|---|---|---|
| 1. Ticker mapping | `ticker_mapping.csv` (already provided) | 35 company → ticker mappings |
| 2. Fetch market cap | `python3 market_cap_utils.py` | `market_cap_data.csv` (245 rows) |
| 3. Build training set | same script | `valuation_training_dataset.csv` (137 rows) |
| 4. Train model | same script | Ridge + Random Forest on log(market_cap) |
| 5. Generate outputs | same script | `model_outputs.csv` (137 company-year rows) + `model_outputs_reviewed.csv` |
| 6. Fetch current prices | same script | `current_market_data.csv` |

Running `python3 market_cap_utils.py` executes all six steps in order.

### Data files

| File | Purpose |
|---|---|
| `ticker_mapping.csv` | Maps XBRL company_id → ticker symbol (35 entries) |
| `market_cap_data.csv` | Per-company-year market cap estimates from yfinance (245 rows, 137 usable) |
| `valuation_training_dataset.csv` | Merged XBRL features + market cap for model training (137 rows) |
| `model_outputs.csv` | All 137 company-year predictions, valuation gap, quality score, research signal |
| `model_outputs_reviewed.csv` | Same as above + `output_quality_flag`, `output_warning_text`, `final_signal_display` |
| `model_output_quality_summary.csv` | Count of each quality flag across all 137 rows |
| `model_metrics.csv` | Ridge / RF / baseline MAE, RMSE, R² (row-based split) |
| `feature_importance.csv` | Random Forest feature importances (top 10) |
| `model_validation_comparison.csv` | Row-based, company-level, and time-based validation metrics side by side |
| `current_market_data.csv` | Live price snapshot per ticker (generated by Step 6) |

**Screener vs. Model Diagnostics — what each shows:**
- The Screener shows **one row per ticker (most recent year)** from `model_outputs_reviewed.csv`.
  Rows flagged as `needs_review` are hidden by default.
- Model Diagnostics reviews **all 137 company-year rows** from `model_outputs_reviewed.csv`,
  including the quality flag breakdown, top-10 gap/error tables, and validation comparison.

### How market cap is estimated

Historical prices from yfinance are **split-adjusted** — NVDA's 2012 adjusted
price appears as ~$0.28 due to its 40× cumulative splits since then. The pipeline
corrects for this by computing the cumulative split factor for all splits that
occurred *after* year-end and multiplying the adjusted price to recover the
approximate historical price (~$11 for NVDA 2012, yielding ~$7B market cap).

XBRL shares-outstanding data is also normalised: some companies switch between
reporting individual shares and thousands; the pipeline detects and corrects this
using a median-based outlier check.

### Model performance (28-observation test set)

| Model | MAE | RMSE | R² |
|---|---|---|---|
| Ridge Regression | ~0.45 log units | ~0.55 | ~0.80 |
| Random Forest | ~0.38 log units | ~0.57 | ~0.79 |
| Mean baseline | ~1.12 log units | ~1.25 | ~−0.02 |

MAE in log units: an MAE of 0.38 means predictions are off by roughly 38% in
log-market-cap space (~46% in dollar terms). Both models substantially beat the
mean baseline.

### Fallback behaviour

If `market_cap_utils.py` has not been run (or fails), the app automatically falls
back to the proxy log(Assets) model and clearly labels it as a size proxy. All
other pages continue to work normally using `sample_data.csv`.

### Limitations

- **In-sample predictions**: `model_outputs.csv` applies the model trained on 80% of rows
  to all 137 rows. 80% of estimates carry in-sample bias.
- **Row-based train/test split**: the current random 80/20 split can be optimistic because
  different years from the same company may appear in both train and test. See
  **Model Validation Methods** below for company-level and time-based alternatives.
- **Small training set**: 27 companies, years 2010–2016. Not validated post-2016.
- **Tech-sector concentration**: training universe is predominantly technology
  companies. Signals may not generalise to other sectors.
- **Report risk placeholder**: all XBRL companies receive Report Risk Score = 50
  (no SEC filing text was parsed for this dataset). Signals are driven by
  valuation gap and quality only.
- **Suspicious data rows**: 16 rows (10 tickers) are flagged `needs_review` due to
  extreme valuation gaps or large model error. ADSK 2011 ($6.85M market cap) is a
  confirmed XBRL shares-units error.
- **Valuation gap is a research signal, not proof of undervaluation.** Benchmark
  comparison is context, not proof of future performance.
- **Not investment advice.** All model outputs are for educational and research
  purposes only.

## Current Screener Mode

The Screener defaults to showing the **latest available model row per ticker** —
one row per company representing the most recent year with model output.

### Live valuation gap

When `current_market_data.csv` is present (generated by `market_cap_utils.py`
Step 6, or refreshed via the in-app button), the Screener computes a live
valuation gap using the current market cap instead of the model-year market cap:

```
valuation_gap_current % =
    (estimated_fair_value_B × 1e9 − current_market_cap) / current_market_cap × 100
```

If the current market cap is unavailable for a ticker, the screener falls back
to the model-year valuation gap. The `valuation_gap_source` column indicates
which was used:

| Value | Meaning |
|---|---|
| `current_mkt` | Live gap — current market cap from `current_market_data.csv` |
| `model_yr` | Fallback — valuation gap at model-year market cap |

### Market snapshot freshness

The freshness of `current_market_data.csv` is shown as a status flag:

| Status | Condition |
|---|---|
| Fresh | File timestamp ≤ 5 hours ago |
| Stale | File timestamp > 5 hours ago |
| Unavailable | File missing or unreadable |

### Refreshing market data

Click **"Refresh market snapshot"** in the Screener sidebar to call
`fetch_current_market_data()` in `data_utils.py`. This re-fetches live prices
and market caps via yfinance and overwrites `current_market_data.csv`.

## Model Validation Methods

The model is evaluated using three complementary split strategies, each saved as a
separate group of rows in `model_validation_comparison.csv`.

### A. Row-based split (current default)

- Randomly assigns 80% of rows to training, 20% to test.
- Fast and standard, but **can overstate performance** because the same company
  (e.g., AAPL) may appear in both train (2012–2015) and test (2016). The model
  has already "seen" that company's financial patterns.
- Label: `validation_type = "row_based"`

### B. Company-level split

- Randomly assigns 80% of **unique tickers** to training, 20% to test.
- Test companies are completely unseen during training — a stricter measure of
  generalization to new companies.
- Lower R² here means the model is partially memorizing company-specific patterns
  rather than learning general financial relationships.
- Label: `validation_type = "company_level"`

### C. Time-based split

- Trains on years <= 2014, tests on years >= 2015.
- Mimics the real-world constraint that a model trained on historical data must
  generalize to future periods.
- Lower R² here means the financial relationships the model learned in 2010–2014
  did not fully hold in 2015–2016.
- Label: `validation_type = "time_based"`

### Why this matters for this project

With only 27 companies and 7 years of data, the training universe is small.
Company-level and time-based R² are expected to be lower than row-based R².
A large drop (> 0.15) is a signal that the model needs more companies or a
different feature engineering approach before its outputs can be trusted as
research signals rather than memorized patterns.

`model_validation_comparison.csv` is generated automatically by
`python3 market_cap_utils.py` and displayed in the **Model Diagnostics** page
under "Validation Comparison".

## Portfolio Simulator

A fully local, simulated portfolio environment. No real trades, no brokerage APIs, no real money.

Two tabs:
- **Live Paper Portfolio** — record simulated trades, track holdings, P/L, and portfolio history
- **Historical Replay** — replay model shortlists against yfinance price data to explore what the model signals would have implied over a chosen holding period

### Live Paper Portfolio features

- **Account setup** — initialize with any starting cash; reset requires confirmation checkbox and warns which files will be deleted
- **Order ticket** — two-column layout: left = order controls, right = position and signal context; no form submission required
- **Shares mode vs Dollars mode** — switch between entering exact shares or a dollar amount; in Dollars mode, estimated shares = dollar amount ÷ trade price, shown in the Order Preview
- **Quick buttons** — Shares mode: 1 share, 5 shares, 10 shares, Max (max affordable for buys / max held for sells); Dollars mode: $100, $500, $1,000, 25% of cash
- **Reference price vs Manual price** — Reference price is loaded automatically from market data; Manual price lets you test a hypothetical trade price; switching to manual shows a price input and flags the trade if the price differs from reference by >$0.01 or >0.1%
- **Manual override detection** — if trade price differs from reference by >$0.01 or >0.1%, the transaction is tagged `manual_override_flag = True` and `price_source` records the deviation
- **Quality flag warning** — if the selected ticker is flagged `needs_review`, a visible warning appears before the order ticket; the simulated trade is not blocked
- **Order preview** — before recording, shows ticker, action, estimated shares, trade price, estimated trade value, available cash, cash after trade; for Reduce: adds average cost, estimated realized P/L, and shares remaining
- **Tooltips** — all key inputs and metrics carry `help=` text: reference price source, manual price caveat, valuation gap meaning, quality score formula, report risk status, estimated realized P/L method, data quality flag meaning
- **Holdings table** — open positions with average cost, current price, market value, unrealized P/L, unrealized P/L %, realized P/L (from prior sells of same ticker), total P/L, portfolio weight %, current signal, valuation gap, and data quality flag
- **Realized P/L tracking** — computed at execution time using average-cost method; stored in `paper_transactions.csv`; shown per position and in portfolio analytics
- **Portfolio analytics** — 10 summary metrics: total value, starting cash, available cash, invested value, total return %, unrealized P/L, realized P/L, open positions, largest position weight, equity exposure; concentration warning if any position >40%
- **Portfolio history** — appends a timestamped snapshot after every page load; chart uses full timestamp when available, date otherwise
- **Benchmark chart** — paper portfolio vs. SPY (normalized to starting cash via yfinance) + cash baseline flat line; fallback message if yfinance fails
- **Transaction history** — filterable by ticker, action, and price source; shows reference price, trade price, manual override flag, and realized P/L columns
- **Downloads** — transactions CSV, holdings CSV, portfolio summary CSV, and a full markdown portfolio report
- **Portfolio report** — plain-text/markdown export with account summary, open positions, closed position realized P/L, benchmark note, and limitations

### Historical Replay features

- **Exact start date** — date picker (not a year selector); model signal year = year of the chosen start date
- **End date mode** — choose "Holding period" (1 month / 3 months / 6 months / 1 year / 2 years / 3 years / 5 years / 10 years / To latest available date) or "Custom end date"
- **Model-backed replay badge** — shown when the signal year exists in model outputs; "Price-only replay" shown when no model output is available for that year
- **Calibrated signals** — if `model_outputs_combined_calibrated.csv` is available, a toggle switches to calibrated signals; "Top calibrated research candidates" becomes an additional selection method
- **Initial capital** — default $10,000, split equally across selected tickers
- **Portfolio size** — Top 3, Top 5, or Top 10 from the model shortlist
- **Selection method** — Research signal priority, Highest valuation gap, Highest quality score, Top calibrated research candidates (when calibration available), or Manual selection via multiselect
- **Exclude needs_review** — checked by default; removes flagged rows before ranking
- **Benchmark** — compare against SPY, QQQ, or a cash baseline (0% return)
- **Replay date summary box** — shows signal year, actual entry date, target exit date, and whether exit was capped at today
- **Model shortlist table** — shows selected tickers with signal, valuation gap, quality score, and data quality flag before running
- **Daily portfolio chart** — line chart with portfolio value, benchmark, and cash baseline from actual entry to exit
- **Replay results** — portfolio return, benchmark return, alpha, and end value; 16-column results table with entry/exit prices and returns
- **Prices cached 1 hour** — yfinance calls use `@st.cache_data(ttl=3600)` so re-running the same config is instant
- **yfinance data** — actual closing prices are fetched via yfinance; split-adjusted, tz-normalized
- **Limitations** — entry is the first available trading day on/after start date; exit is the last available trading day on/before target exit date; no dividends, taxes, or slippage; benchmark comparison is context, not a performance claim

All three files are created automatically. **Initialize / Reset Account** deletes all three and resets to the entered starting cash.

### Average-cost accounting method

Positions use the **average cost** method:
- Each buy adds shares and cost: `avg_cost = total_cost / total_shares`
- `avg_cost` does not change when shares are sold
- Realized P/L per sell trade: `(trade_price − avg_cost) × quantity`
- After a full close, avg_cost resets to 0 for that ticker

## Key Formulas

**Quality Score (0–100):**
```
= 0.30 × ROE_score
+ 0.25 × FCF_Yield_score
+ 0.25 × Revenue_Growth_score
+ 0.20 × LowDebt_score
```

**Report Risk Score (0–100):**
Based on normalized counts of risk keywords, debt/liquidity language,
legal/litigation mentions, and cost pressure language in SEC filings.

## Modern Fundamentals Expansion

### Why the original model stops at 2016

The original valuation model was built on an XBRL dataset (`XBRL/companies.csv` +
`XBRL/indicators_by_company.csv`) covering fiscal years 2010–2016. Expanding
Historical Replay beyond 2016 requires fundamentals data for newer years.

### Approach: SEC EDGAR Company Facts API

The `modern_fundamentals_utils.py` pipeline uses the free, official SEC EDGAR
Company Facts API (`https://data.sec.gov/api/xbrl/companyfacts/CIK{10-digit}.json`)
to fetch annual GAAP fundamentals for 2017–present for the same 27+ tickers.

**Before running:** set the `SEC_USER_AGENT` environment variable with your name
and email (SEC access policy requires identification):

```bash
export SEC_USER_AGENT="Your Name your.email@example.com"
```

Or edit the default directly in `modern_fundamentals_utils.py`.

### How to run

```bash
python3 modern_fundamentals_utils.py
```

This executes the full 7-step pipeline (~5–10 min, mostly SEC fetch + yfinance):

1. Load CIK mapping from `ticker_mapping.csv` (company_id = SEC CIK)
2. Fetch SEC Company Facts JSON for each ticker (cached locally)
3. Extract annual fundamentals (2017–present)
4. Fetch year-end market caps via yfinance
5. Build modern training dataset
6. Train valuation model on combined legacy + modern data
7. Merge outputs → `model_outputs_combined.csv`

### Ticker→CIK mapping

`ticker_cik_mapping.csv` is auto-created from `ticker_mapping.csv` on first run.
The `company_id` column in `ticker_mapping.csv` IS the SEC CIK for all tickers in
this dataset (verified: Microsoft CIK 0000789019 = company_id 789019).

### SEC Company Facts cache

Fetched JSON files are cached in `sec_company_facts_cache/` (one file per company,
named `CIK0000789019.json`). Re-running the pipeline uses cached files — re-fetching
is only triggered if the cache file is deleted.

### Files generated

| File | Purpose |
|---|---|
| `sec_company_facts_cache/*.json` | Cached SEC EDGAR responses |
| `ticker_cik_mapping.csv` | Ticker ↔ CIK lookup table |
| `modern_fundamentals.csv` | Annual SEC fundamentals 2017–present |
| `modern_market_cap_data.csv` | Year-end market caps via yfinance |
| `modern_valuation_training_dataset.csv` | Merged training data |
| `modern_model_outputs.csv` | Model signals for 2017–present |
| `model_outputs_combined.csv` | 2010–2016 XBRL + 2017–present SEC |

### How combined outputs enable newer Historical Replay years

Once `model_outputs_combined.csv` exists:
- Historical Replay automatically reads it instead of `model_outputs_reviewed.csv`
- The year selector shows all available years (potentially 2010–2024)
- Model-backed signals are available for both legacy and modern years
- If the combined file is missing, the app falls back to legacy outputs (2010–2016)

### Limitations

- `report_risk_score = 50` (neutral) for all modern outputs — SEC filing text
  extraction is not integrated. Report risk does not reflect actual filing sentiment.
- Market caps are estimated: year-end price × shares outstanding from SEC facts.
  Split adjustments may introduce small errors for years before splits occurred.
- Revenue concept mapping differs between GAAP periods: pre-2018 uses `Revenues`;
  post-2018 uses `RevenueFromContractWithCustomerExcludingAssessedTax` (ASC 606).
  The pipeline tries both, preferring the more specific modern concept.
- Historical replay results are simplified research exercises, not backtests.
  No survivorship bias correction, taxes, slippage, or dividend reinvestment.

## Signal Calibration

### Why calibration is needed

The valuation model was trained on 2010–2016 data. In that era, companies with a
valuation gap below −10% were labeled "Potentially overvalued" based on how gaps
were distributed during training. Post-2017 market valuations are structurally
higher — tech companies routinely trade at much higher multiples. Applying the same
fixed thresholds to 2021–2024 data causes 79% of 2021 companies to be labeled
"Potentially overvalued," which is not useful as a research signal.

### What calibrated signals do

Calibrated signals compute each company's **percentile rank within the same year
(and within the same market era)**, then assign a signal based on relative position:

| Percentile (within year) | Bucket |
|---|---|
| ≥ 90th | Top decile relative value |
| 70th–90th | Above-average relative value |
| 40th–70th | Neutral relative value |
| 20th–40th | Below-average relative value |
| < 20th | Low relative value |

A company in the "Top decile relative value" bucket with quality ≥ 50 becomes
"Research candidate." The same company using absolute thresholds might have been
labeled "Potentially overvalued" simply because the entire 2021 cohort had lower
gaps than the 2010–2016 training regime.

### Original signal vs. calibrated signal

- **Original signal** — uses fixed absolute thresholds (gap > 10% = Research candidate,
  gap < −10% = Potentially overvalued). Consistent across all years but biased against
  modern eras.
- **Calibrated signal** — uses year-level percentile ranking. More meaningful for
  comparing companies within the same year. Both signals are visible in Company Detail.

Neither signal is investment advice. Both are research signals that indicate where
to focus research time, not whether to buy or sell.

### Combined model validation

After running `calibrate_signals.py`, run:

```bash
python3 validate_combined_model.py
```

This evaluates the combined 2010–2024 model across four splits and saves
`combined_model_validation_comparison.csv`. Results are displayed in
**Model Diagnostics → Combined Model Validation**.

### Files generated by `calibrate_signals.py`

Run: `python3 calibrate_signals.py`

| File | Purpose |
|---|---|
| `signal_distribution_by_year.csv` | Original and calibrated signal counts/pcts by year |
| `valuation_gap_distribution_by_era.csv` | Valuation gap percentiles by market era |

When loading model outputs, the app prefers:
1. `model_outputs_combined_calibrated.csv` — best: all years + calibrated signals
2. `model_outputs_combined.csv` — all years, original signals only

## SEC Filing Risk Extraction

### What it does

`filing_risk_utils.py` downloads annual 10-K filings from SEC EDGAR for each
company in the model outputs, extracts risk-related language from the
"Item 1A — Risk Factors" section (or full text as fallback), and computes a
**filing risk score (0–100)** for each company-year.

Higher score = more risk-related language in the filing relative to dataset peers.
This is a research signal, not a prediction of stock performance.

### How to run

```bash
export SEC_USER_AGENT="Your Name your.email@example.com"
python3 filing_risk_utils.py
```

First run takes ~5–15 minutes (fetching ~435 filings). Subsequent runs use the
local cache and complete in seconds.

### How risk scores are computed

1. **Filing lookup** — SEC EDGAR submissions API maps each ticker+year to its
   10-K accession number and primary document.
2. **Text extraction** — downloads the primary 10-K document (HTML or TXT),
   strips formatting, and extracts the "Item 1A Risk Factors" subsection where
   detectable; falls back to full filing text capped at 300K characters.
3. **Keyword counting** — counts occurrences of risk-related phrases in five
   categories:

   | Category | Weight | Examples |
   |---|---|---|
   | General risk density | 30% | risk, uncertain, adverse, volatile |
   | Debt/liquidity | 25% | debt, leverage, liquidity, covenant |
   | Legal/regulatory | 20% | litigation, investigation, enforcement |
   | Uncertainty/adverse | 15% | material adverse, impairment, write-down |
   | Cost pressure / cyber | 10% | inflation, supply chain, cybersecurity |

4. **Percentile scoring** — each company-year is ranked within the full dataset
   on each normalized metric; weighted percentile combination gives the final
   0–100 score.

### How missing filings are handled

If a 10-K cannot be found or parsed:
- `report_risk_score` remains 50 (neutral placeholder)
- `filing_data_quality_flag` is set to `filing_missing` or `parse_error`
- `risk_score_source` is `filing_missing_or_error`
- The calibrated signal is unchanged

### How signals change after risk adjustment

- If `report_risk_score_real ≥ 80` and calibrated signal is "Research candidate":
  - Quality < 45: downgraded to "Possible value trap"
  - Quality ≥ 45: downgraded to "Fairly valued / neutral" with warning
- Otherwise: calibrated signal is unchanged
- The `final_signal_calibrated_risk_adjusted` column stores the adjusted signal
- `risk_adjustment_reason` stores the plain-English reason for any change

### Files generated

| File | Purpose |
|---|---|
| `sec_filing_index_cache/*.json` | Cached SEC submissions metadata per company |
| `sec_filing_text_cache/*.txt` | Cached plain-text per filing |
| `filing_lookup_results.csv` | Which 10-K was found for each ticker+year |
| `filing_risk_features.csv` | Raw risk keyword counts per filing |
| `filing_risk_scores.csv` | Final 0–100 risk scores per ticker+year |
| `model_outputs_combined_calibrated_risk.csv` | Calibrated outputs + risk scores |

### App fallback chain (updated)

1. `model_outputs_combined_calibrated_risk.csv` — best: all years + calibrated + filing risk
2. `model_outputs_combined_calibrated.csv` — all years + calibrated signals
3. `model_outputs_combined.csv` — all years, original signals only
4. `model_outputs_reviewed.csv` — legacy 2010–2016, quality-reviewed
5. `model_outputs.csv` — base legacy output

### Limitations

- Report risk is computed from filing language only, not auditor opinions,
  market conditions, or forward-looking performance data.
- Very long filings are capped at 300K characters; the tail is not analyzed.
- Some filings may have HTML structure that prevents clean text extraction,
  causing `parse_error` and a neutral placeholder score.
- Companies with no 10-K on EDGAR (e.g., foreign private issuers filing 20-F)
  may not be found; the script will log the failure and continue.
- Filing text is downloaded and cached locally; disk usage is approximately
  5–50 MB per 100 filings depending on filing size.
- Not investment advice. Filing risk score is a research signal only.

## 10-Q Quarterly Risk Update

### Annual 10-K vs. quarterly 10-Q

| | 10-K (annual) | 10-Q (quarterly) |
|---|---|---|
| **Role** | Baseline filing risk signal, used as a model input | Latest quarterly update, supplemental context only |
| **Used in model** | Yes — `report_risk_score_real` feeds `final_signal_calibrated_risk_adjusted` | No — does not replace or modify the annual model signal |
| **Coverage** | One filing per fiscal year (2010–2024) | Most recent 10-Q for each ticker |
| **Output file** | `filing_risk_scores.csv`, `model_outputs_combined_calibrated_risk.csv` | `latest_10q_risk_scores.csv`, `filing_risk_current_update.csv` |

The 10-Q pipeline is a **separate, supplemental** layer. It provides a
current-quarter risk snapshot and a trend indicator (is filing risk language
increasing or decreasing relative to the annual baseline?) but does not change
the model's calibrated signal.

### How to run

```bash
export SEC_USER_AGENT="Your Name your.email@example.com"

# Run the full annual 10-K pipeline (if not already done):
python3 filing_risk_utils.py

# Run the 10-K pipeline, then add the 10-Q update in one pass:
python3 filing_risk_utils.py --10q

# Run only the 10-Q update (skip 10-K if it has already been done):
python3 filing_risk_utils.py --10q-only
```

### Output files

| File | Purpose |
|---|---|
| `sec_filing_10q_cache/*.txt` | Cached plain-text of each company's latest 10-Q |
| `latest_10q_risk_scores.csv` | Per-ticker 10-Q risk scores (0–100) and raw keyword counts |
| `filing_risk_current_update.csv` | 10-K vs. 10-Q comparison: delta score and trend label |

### Trend logic

`filing_risk_current_update.csv` includes a `filing_risk_trend` column computed
by comparing each ticker's latest 10-Q risk score against its most recent annual
10-K risk score:

| Condition | `filing_risk_trend` |
|---|---|
| `latest_10q_risk_score − annual_10k_risk_score >= +10` | Increasing |
| `latest_10q_risk_score − annual_10k_risk_score <= −10` | Decreasing |
| Within ±10 points | Stable |
| 10-Q score unavailable | Unavailable |

### Columns in `latest_10q_risk_scores.csv`

| Column | Description |
|---|---|
| `ticker` | Ticker symbol |
| `company_name` | Company name from CIK mapping |
| `cik` | SEC CIK |
| `latest_10q_filing_date` | Date the 10-Q was filed with the SEC |
| `latest_10q_period` | Fiscal period covered by the 10-Q |
| `latest_10q_form_type` | Always "10-Q" |
| `latest_10q_risk_score` | 0–100 percentile risk score (same scale as 10-K) |
| `latest_10q_risk_words_per_1000` | General risk keyword density |
| `latest_10q_debt_liquidity_mentions` | Debt/liquidity keyword count |
| `latest_10q_legal_regulatory_mentions` | Legal/regulatory keyword count |
| `latest_10q_uncertainty_mentions` | Uncertainty/adverse keyword count |
| `latest_10q_cost_cyber_mentions` | Cost pressure + cybersecurity keyword count |
| `latest_10q_data_quality_flag` | `ok`, `not_found`, `parse_error`, etc. |
| `latest_10q_warning_text` | Human-readable explanation for non-ok flags |

### Safety note

- The app runs with all CSVs missing — every pipeline output has a graceful
  fallback (placeholder scores, neutral signals, or hidden columns).
- XBRL raw files (`XBRL/companies.csv`, `XBRL/indicators_by_company.csv`) are
  only required if rebuilding the original 2010–2016 pipeline from scratch.
- Normal app users can run from the pre-generated CSVs without re-running any
  pipeline script.

### Limitations

- 10-Q scores are computed relative to the other 10-Q filings in the current
  run — not against the 10-K percentile baseline. Use delta/trend for comparison.
- Not all companies file 10-Qs (e.g., some foreign issuers). These are flagged
  `not_found`.
- The cached 10-Q text reflects the most recent filing at the time of the last
  run. Delete `sec_filing_10q_cache/` to force a fresh download.
- The 10-Q update does not affect model signals. It is a supplemental research
  signal only — not investment advice.
